第26课：多平台适配

如何让一个SwiftUI项目适配iOS、iPadOS、macOS、watchOS

课程概述

SwiftUI 是苹果推出的声明式 UI 框架，其核心优势之一就是能够用一套代码为苹果的所有平台（iOS、iPadOS、macOS、watchOS，甚至 tvOS）构建应用程序。本课将深入讲解如何利用 SwiftUI 的特性，高效地进行多平台适配，打造真正的通用应用程序。

核心思想：SwiftUI 鼓励你首先构建应用程序的核心逻辑和共享 UI，然后针对每个平台的独特功能和交互模式进行优化，而不是为每个平台编写完全独立的代码。

一、项目设置与目标平台

在 Xcode 中创建新项目时，选择 “Multiplatform” 模板下的 “App”。这将自动为你创建支持 iOS、iPadOS、macOS 等平台的项目结构。

项目结构概览

  • 共享代码 (Shared): 存放所有平台通用的模型、视图、视图模型和工具类。
  • 平台特定代码 (iOS, macOS, watchOS): 存放仅适用于特定平台的视图、应用入口和资源。
  • 资源 (Assets): 可以包含通用资源和平台特定资源。

二、平台差异与条件编译

使用条件编译指令 #if os() 来区分不同平台的代码。这是进行平台适配的基础。

import SwiftUI

struct ContentView: View {
    var body: some View {
        VStack {
            #if os(iOS)
            Text("这是在 iPhone 或 iPad 上运行")
                .font(.title)
            #elseif os(macOS)
            Text("这是在 Mac 上运行")
                .font(.largeTitle)
            #elseif os(watchOS)
            Text("这是在 Apple Watch 上运行")
                .font(.caption)
            #endif

            // 共享的视图部分
            Image(systemName: "applelogo")
                .foregroundColor(.blue)
        }
    }
}
编译条件 适用平台 常用场景
#if os(iOS) iOS, iPadOS 适配触控交互、紧凑布局
#if os(macOS) macOS 添加菜单命令、调整窗口样式
#if os(watchOS) watchOS 简化界面、适配圆形屏幕
#if targetEnvironment(macCatalyst) Mac Catalyst (iPad应用转Mac) 优化Mac端特有交互

三、自适应布局与尺寸类别

SwiftUI 提供了强大的布局工具，如 VStack, HStack, Grid，以及环境值 @Environment(\.horizontalSizeClass) 来创建自适应的界面。

使用 SizeClass 适配

struct AdaptiveView: View {
    @Environment(\.horizontalSizeClass) var horizontalSizeClass

    var body: some View {
        if horizontalSizeClass == .compact {
            // 紧凑宽度（如iPhone竖屏）
            VStack {
                // 垂直排列内容
                DetailView()
                ListView()
            }
        } else {
            // 常规宽度（如iPad、Mac、iPhone横屏）
            HStack {
                // 水平分栏
                ListView()
                    .frame(width: 250)
                DetailView()
            }
        }
    }
}

提示：对于 watchOS，屏幕尺寸非常有限，应优先考虑使用 ScrollView 和简单的垂直堆栈，并尽量减少页面层级。

四、平台特定功能与修饰符

不同平台支持不同的交互方式和系统功能。SwiftUI 通过修饰符和场景API来处理这些差异。

1. 导航差异

// 在iOS/iPadOS上使用 NavigationStack
#if os(iOS)
NavigationStack {
    List(items) { item in
        NavigationLink(value: item) {
            Text(item.name)
        }
    }
    .navigationDestination(for: Item.self) { item in
        DetailView(item: item)
    }
}
#endif

// 在macOS上通常使用侧边栏+详情页的导航样式
#if os(macOS)
NavigationSplitView {
    List(items, selection: $selectedItem) { item in
        Text(item.name)
            .tag(item)
    }
} detail: {
    if let selectedItem {
        DetailView(item: selectedItem)
    } else {
        Text("请选择一项")
    }
}
#endif

2. 窗口与场景管理 (macOS)

// 在 macOS 的 App 入口中定义窗口和菜单
@main
struct MyMacApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .commands {
            // 添加应用菜单
            CommandMenu("编辑") {
                Button("复制") {
                    // 复制操作
                }
                .keyboardShortcut("c")
            }
        }

        #if os(macOS)
        Settings {
            SettingsView() // macOS 特有的设置窗口
        }
        #endif
    }
}

五、资源与图标的适配

在 Asset Catalog 中，可以为不同平台提供不同的图片、颜色和图标资源。

  • 应用图标： 每个目标都有独立的 AppIcon 资源集，需分别配置。
  • 图片资源： 使用 Image("name")，SwiftUI 会自动选择当前平台可用的最佳资源。
  • 符号图标 (SF Symbols)： 优先使用，它们在不同平台上表现一致且可自动适配。

六、最佳实践总结

实践原则 具体做法 收益
最大化共享代码 将数据模型、网络逻辑、业务核心放在 Shared 目录 减少重复，维护单一信源
渐进式平台优化 先构建通用版本，再使用条件编译添加平台增强功能 快速上线，迭代优化
尊重平台习惯 iOS用导航栏，macOS用菜单和窗口，watchOS用垂直滚动 符合用户直觉，提升体验
利用 SwiftUI 抽象 使用 ViewBuilder, ViewModifier 封装平台差异 代码更清晰，复用性高
充分测试 在每种目标设备和模拟器上运行测试 确保各平台功能与UI正常

最终目标： 不是追求 100% 的代码共享，而是在代码复用和提供最佳原生体验之间找到完美的平衡点。让你的应用在每个平台上都感觉“像家一样”，而不是一个简单的移植品。
