第29课：SwiftUI性能优化

识别并解决视图重绘、列表性能等瓶颈

引言：为什么需要性能优化？

SwiftUI 通过声明式语法和自动的视图更新机制极大地提升了开发效率。然而，不恰当的使用会导致不必要的视图重绘、内存增长和界面卡顿，严重影响用户体验。本课将深入探讨常见的性能瓶颈及其解决方案。

一、核心性能瓶颈识别

SwiftUI 的性能问题通常源于以下几个方面：

  • 不必要的视图重绘（Re-rendering）：状态变化导致整个视图树无效更新。
  • 低效的列表（List）与滚动视图：大量数据项未优化，导致滚动卡顿。
  • 内存泄漏与循环引用：Combine 管道或闭包使用不当。
  • 昂贵的视图主体计算：视图的 body 属性内包含复杂逻辑。
  • 图片与资源处理：未缓存或未正确缩放图片。

二、优化策略与实战代码

1. 减少视图重绘：使用 EquatableView 与自定义相等判断

默认情况下，SwiftUI 在状态变化时会重新计算视图的 body。通过让视图遵守 Equatable 协议，可以自定义相等性比较，避免不必要的刷新。

struct UserProfileView: View, Equatable {
    let user: User
    let lastUpdated: Date

    var body: some View {
        VStack {
            Text(user.name)
                .font(.title)
            Text("更新于: \(lastUpdated, formatter: dateFormatter)")
        }
    }

    static func == (lhs: UserProfileView, rhs: UserProfileView) -> Bool {
        // 仅当用户ID和最后更新时间相同时才认为相等，避免重绘
        return lhs.user.id == rhs.user.id && lhs.lastUpdated == rhs.lastUpdated
    }
}

2. 列表性能优化：使用 Identifiable 与差异化数据

对于大型列表，确保数据模型遵守 Identifiable 和 Hashable，以便 SwiftUI 高效识别和更新项。

struct Book: Identifiable, Hashable {
    let id = UUID()
    let title: String
    let author: String
    let pageCount: Int
}

struct BookListView: View {
    let books: [Book]

    var body: some View {
        List(books) { book in
            BookRow(book: book)
                .listRowBackground(Color.clear)
        }
        .listStyle(PlainListStyle())
    }
}

struct BookRow: View {
    let book: Book

    var body: some View {
        VStack(alignment: .leading) {
            Text(book.title)
                .font(.headline)
            Text(book.author)
                .font(.subheadline)
                .foregroundColor(.secondary)
        }
        .padding(.vertical, 8)
    }
}
提示： 对于超长列表，考虑使用 LazyVStack 或 LazyHStack 配合 ScrollView，实现按需加载。但需注意，List 自带复用机制，而 LazyStack 需要手动管理复用。

3. 状态与绑定优化：精细控制依赖

避免使用高阶状态（如整个对象）作为依赖，应提取最小必要属性。

// 不推荐：整个对象变化都会触发重绘
@StateObject var userManager = UserManager()

// 推荐：仅观察必要属性
@State private var userName: String = ""
@State private var isActive: Bool = false

// 使用 .onReceive 监听特定发布者
.onReceive(userManager.$name) { newName in
    userName = newName
}

四、检查清单与最佳实践

  1. 视图结构扁平化：避免过深的视图嵌套，减少布局计算。
  2. 使用 @ViewBuilder 构建复杂条件视图：将条件逻辑移至 @ViewBuilder 属性或方法中。
  3. 图片与动画优化：
    • 使用 resizable(capInsets:resizingMode:) 和 aspectRatio(contentMode:) 调整图片。
    • 对于重复使用的图片，考虑缓存到 NSCache 或使用第三方库。
    • 使用 withAnimation 精确控制动画范围。
  4. 利用 Instruments 定期分析：使用 Time Profiler 和 Allocations 工具定位热点。
  5. 在真机上测试性能：模拟器无法完全反映真实设备的性能表现。
