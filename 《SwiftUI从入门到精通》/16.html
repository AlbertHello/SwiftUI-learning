SwiftUI从入门到精通

第16章：场景与窗口：App协议、WindowGroup、DocumentGroup、多窗口与场景管理

在SwiftUI中，应用的结构和窗口管理通过全新的声明式API进行了重构。本章将深入探讨 @main 应用入口、App 协议、以及用于创建多窗口和文档型应用的核心组件：WindowGroup 和 DocumentGroup。

核心概念： SwiftUI 2.0 引入了基于场景(Scene)的应用架构，将应用分解为多个独立的界面单元，每个单元可以独立管理自己的窗口和生命周期。

一、App协议与 @main 入口

SwiftUI应用从一个符合 App 协议的结构体开始，并使用 @main 属性标记为入口点。

import SwiftUI

@main
struct MyFirstApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
  • @main: 标识应用入口点，系统会自动调用该结构体的 main() 方法。
  • App协议: 要求实现一个 body 属性，返回一个 Scene。
  • Scene: 描述应用用户界面的一部分，通常对应一个窗口或一组窗口。

二、WindowGroup：多窗口应用基石

WindowGroup 是创建支持多窗口应用的主要场景。它为其中的视图提供一个共享的“模板”，用户可以从中创建多个窗口实例。

@main
struct MultiWindowApp: App {
    var body: some Scene {
        WindowGroup("我的笔记") { // 设置窗口标题
            NoteListView()
        }
        .commands {
            // 添加自定义菜单命令
            CommandMenu("笔记") {
                Button("新建笔记") { /* 操作 */ }
                Button("搜索") { /* 操作 */ }
            }
        }
    }
}

WindowGroup 的关键特性

特性 说明 示例/备注
多窗口支持 用户可通过菜单（“文件”->“新建”）或快捷键（Cmd+N）创建新窗口 系统自动管理窗口生命周期
场景修饰符 可设置窗口标题、默认大小、角色等 .windowStyle(.titleBar), .defaultSize(width: 400, height: 300)
环境共享 同一WindowGroup内的所有窗口共享应用状态和环境对象 通过 @EnvironmentObject 传递数据模型
命令菜单 向菜单栏添加自定义命令 在 .commands 闭包中定义

三、DocumentGroup：文档型应用

DocumentGroup 专为处理文档的应用设计，它自动集成文件打开、保存、版本管理等功能。

import UniformTypeIdentifiers

@main
struct TextEditorApp: App {
    var body: some Scene {
        DocumentGroup(newDocument: TextFile()) { file in
            TextEditorView(document: file.$document)
        }
    }
}

// 定义文档模型
struct TextFile: FileDocument {
    static var readableContentTypes: [UTType] { [.plainText] }
    var document: String = ""
    
    init(configuration: ReadConfiguration) throws {
        if let data = configuration.file.regularFileContents {
            document = String(decoding: data, as: UTF8.self)
        }
    }
    
    func fileWrapper(configuration: WriteConfiguration) throws -> FileWrapper {
        let data = Data(document.utf8)
        return FileWrapper(regularFileWithContents: data)
    }
}

WindowGroup 适用场景

  • 工具类应用（计算器、日历）
  • 多窗口信息展示（仪表盘）
  • 不需要传统“文件”概念的应用
  • 单视图多实例应用

DocumentGroup 适用场景

  • 文本编辑器（如TextEdit）
  • 图像处理软件
  • 任何需要“打开/保存”文件的应用
  • 支持自动保存和版本的应用

四、多窗口与场景管理

SwiftUI 支持在单个应用中定义多个场景，实现标签页、侧边栏等复杂界面。

多场景配置示例

@main
struct ProfessionalApp: App {
    var body: some Scene {
        // 主窗口
        WindowGroup("工作区", id: "main-workspace") {
            MainWorkspaceView()
        }
        .defaultSize(width: 1000, height: 700)
        
        // 辅助工具窗口
        WindowGroup("工具面板", id: "tool-panel") {
            ToolPanelView()
        }
        .defaultSize(width: 300, height: 500)
        
        // 文档编辑窗口
        DocumentGroup(newDocument: SketchDocument()) { file in
            SketchEditorView(document: file.$document)
        }
        
        // 设置窗口 (macOS)
        #if os(macOS)
        Settings {
            SettingsView()
        }
        #endif
    }
}
提示： 通过为每个 WindowGroup 指定唯一的 id，可以更好地控制窗口的创建和恢复。系统会记住每个场景的窗口状态，并在应用重启时恢复。

五、场景管理最佳实践

  1. 合理划分场景：将功能独立的界面单元放在不同的场景中，便于独立管理生命周期和状态。
  2. 使用环境对象共享数据：对于需要在多个窗口间共享的数据，使用 @EnvironmentObject 或 @StateObject。
  3. 考虑平台差异：iOS 和 macOS 在窗口管理上有显著差异，使用条件编译（#if os(macOS)）处理平台特定代码。
  4. 利用场景恢复：系统会自动保存和恢复窗口状态，确保应用数据结构支持 Codable 协议以充分利用此功能。
  5. 管理窗口焦点：使用 @FocusedValue 或 @FocusedBinding 来响应当前焦点窗口的变化。

场景生命周期管理代码示例

// 使用ScenePhase监控场景状态
struct MyApp: App {
    @Environment(\.scenePhase) private var scenePhase
    
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .onChange(of: scenePhase) { newPhase in
            switch newPhase {
            case .active:
                print("场景激活")
            case .inactive:
                print("场景失活")
            case .background:
                print("场景进入后台")
            @unknown default:
                break
            }
        }
    }
}

六、本章总结

组件/概念 核心作用 关键点
App协议 定义SwiftUI应用的结构和入口 使用@main标记，返回Scene
WindowGroup 创建支持多窗口的界面场景 自动窗口管理，共享状态，支持菜单命令
DocumentGroup 构建文档型应用 集成文件操作，自动实现打开/保存逻辑
多场景配置 在单个应用中定义多个界面单元 可混合使用WindowGroup、DocumentGroup、Settings等
场景管理 监控和控制场景生命周期 使用ScenePhase，支持状态恢复，平台适配

SwiftUI的场景系统为现代应用开发提供了强大而灵活的架构。通过 WindowGroup 和 DocumentGroup，开发者可以轻松创建从简单工具到复杂文档编辑器的各种应用，同时享受系统级的窗口管理、状态恢复和跨平台支持。
